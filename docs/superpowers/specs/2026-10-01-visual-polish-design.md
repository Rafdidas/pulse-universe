# 화면 다듬기 설계

- 작성일: 2026-10-01
- 상태: 초안 (사용자 검토 대기, 시제품 확인 전)
- 선행: 태양계 배치(`solar.ts`/`layout.ts`), 이름표·범례, 코어 고리 (`main` b9ae5c8)
- 범위: 스크린샷에서 보인 네 가지 — 이름표가 별 빛 위에 놓임, 순위가 흔들릴 때 궤도를 옮겨 다님, 중심부 천체가 별과 겹침, 한가한 CPU 코어가 너무 작음 — 을 고친다. 코어 번호 라벨, 새 상호작용, 프로토콜·엔진 변경은 범위 밖이다.

## 3. 이름표 배치 (D91)

- `web/src/visual/labelPlacement.ts` (새 파일, three 를 모르는 순수 모듈):
  - 입력: 이름표마다 `key`, 천체의 화면 중심 `(sx, sy)` px, 화면 반지름 `radiusPx`, 이름표 크기 `(width, height)` px, `wasVisible`; 별의 화면 중심 `(sx, sy)`.
  - 방향 `d` = 별→천체의 단위 벡터 (길이가 0 에 가까우면 위쪽 `(0,-1)`). 이름표 중심 = 천체 중심 + `d·(radiusPx + GAP + half)`, `half = |d.x|·width/2 + |d.y|·height/2`, `GAP = 4`.
  - 겹침: `wasVisible` 이 참인 것, 그다음 `radiusPx` 가 큰 것, 같으면 `key` 순으로 훑으며 이미 받아들인 상자와 (패딩 2 px 포함) 겹치면 숨긴다. 출력은 입력과 같은 순서의 `{key, visible, cx, cy}`.
- `web/src/scene/BodyLabels.tsx`: 지금은 이름표마다 `useFrame` 이 앵커를 옮긴다. 모든 이름표를 한 번에 계산해야 하므로 `useFrame` 하나가 이름표 전부를 계산하도록 바꾼다. 천체의 월드 위치(부유 포함)를 카메라로 화면 좌표와 깊이로 바꾸고(`radiusPx = radius·(height/2)/(tan(fov/2)·depth)`), 별(원점)도 같이 바꾼 뒤 `placeLabels` 를 부르고, 결과를 DOM 에 직접 쓴다 (프레임 값은 React 상태에 넣지 않는다). 이름표는 천체 위치에 앵커를 두고 `transform: translate(dx px, dy px)` 로 `placeLabels` 가 정한 자리로 옮긴다. 이름표 폭은 이름이 바뀔 때 한 번 재서 캐시한다.
- 기존 규칙은 그대로다: 초점이 잡히면(`weight > 0.5`) 숨김, 호버 중인 그룹의 이름표 숨김, 사라지는 중인 그룹 숨김. 이름표 대상(`labelKeys`)과 개수(`MAX_LABELS`)는 변하지 않는다.

## 4. 배치 안정화 (D92)

- `layout.ts`: `RADIUS_DEADBAND = 0.1`. `OrbitLayout` 에 `Map<key, number>`(배치용 반지름)를 둔다. `step` 에서 노드마다 `s = map.get(key) ?? node.radius`, `|node.radius / s − 1| > RADIUS_DEADBAND` 이면 `s = node.radius`, 저장. 그 `s` 를 반지름으로 한 노드 목록으로 `planOrbits` 를 부른다. 사라진 key 는 지운다. 처음 보는 key 는 실제 반지름이 곧 배치용 반지름이다.
- `planOrbits` 는 그대로(순수). `OrbitLayout.plan()` 은 배치용 반지름으로 만든 계획을 돌려준다 (궤도선과 이름표 대상이 쓴다).
- 그려지는 천체의 크기, 위성, 툴팁은 실제 반지름을 쓴다. 배치용 반지름과의 차이는 10 % 이내이고 `ARC_GAP`·`RING_GAP` 의 여유로 충분하다 (`body-body` 겹침은 시제품에서 다시 측정한다).

## 5. 중심부와 코어 (D93, D94)

- `solar.ts`: `STAR_GAP = 3.0` → `7.0`, 해당 주석의 숫자 갱신.
- `camera.ts`: `OVERVIEW_POSE.position` → `{ x: 0, y: 60, z: 58 }`.
- `coreRing.ts`: `RING_MIN_RADIUS = 34` → `38`, 주석의 "끝 약 27" 을 새 값(약 31)으로 고친다.
- `coreMapping.ts`: `orbRadius` 를 `1.0 + 0.9 * clamp01(load)`, 주석 "0.7 ~ 1.6" → "1.0 ~ 1.9".
- 위 상수를 숫자로 고정한 테스트와 문서(`web/README.md`, 루트 `README.md`)의 숫자를 새 값으로 맞춘다.

## 6. 테스트

- `labelPlacement`: 방향이 별 반대쪽, 별과 같은 위치일 때 위쪽, 두 상자 겹침 시 큰 쪽 유지, `wasVisible` 우선, 정렬 결정성(같은 입력 → 같은 출력), 이름표가 하나일 때, 빈 입력, 패딩 경계.
- `OrbitLayout` 안정화: 반지름이 ±9 % 흔들려도 궤도 변경 없음, 11 % 넘게 변하면 옮겨 감, 새 key 는 실제 반지름으로 시작, 사라진 key 정리, 같은 입력은 같은 결과(결정성), 기존 테스트(큰 변화로 궤도 이동 등)는 그대로 통과.
- 상수 테스트: `solar`(STAR_GAP 으로 첫 궤도 반지름), `camera`(개요 자세), `coreRing`(최소 반지름), `coreMapping`(`orbRadius` 양끝 1.0·1.9)을 새 값으로.
- 시제품 측정을 `tests/visual/` 의 회귀 시험으로 남긴다: 픽스처로 600 초 훑으며 이름표(바깥 배치)가 별 빛 위에 놓이는 프레임 0 %, 별 빛에 겹치는 천체 평균 0.2/40 미만, 잡음 모형에서 분당 궤도 이동 1 회 미만.
- 화면 확인: 엔진을 띄우고 브라우저 스크린샷으로 이름표 위치와 중심부를 눈으로 비교한다 (이전 스크린샷과 나란히). 숨겨진 창은 스크린샷 때만 그려진다는 점 때문에 카메라 전환 등은 본다고 하지 않는다.

## 7. 완료 조건

- 이름표가 별 빛 위에 놓이지 않고, 겹치면 작은 것이 숨는다.
- 메모리가 조금 흔들려도 천체가 궤도를 옮기지 않는다.
- 중심부 큰 천체가 별 빛과 겹치지 않는다.
- 한가한 코어도 알아볼 수 있다.
- 웹 테스트·타입체크·린트 통과, 아키텍처 규칙 유지 (`visual/**` 순수, 프레임 값은 React 상태 금지).

## 8. 범위 밖

코어 번호 라벨, 이름표 개수·대상 변경, 새 카메라 조작, 위성 궤도 변경, 엔진·프로토콜 변경, 색상 팔레트 변경.
