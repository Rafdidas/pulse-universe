# M5 — 생성·종료 연출, Focus, 카메라 설계

- 작성일: 2026-09-28
- 상태: 승인 대기
- 선행: 계약서 `2026-09-22-pulse-universe-contract-design.md`, M4 `2026-09-28-m4-universe-scene-design.md`, M1~M4 구현 (`main`)
- 범위: 프로세스의 실제 생성·종료를 파티클로 연출하고, 순위 변동은 조용히 페이드한다. 천체를 클릭하면 카메라가 다가가고 자식 프로세스가 위성으로 펼쳐진다. 엔진의 목록 안정화와 샘플링 주기 결함 수정을 포함한다.

## 1. 이 문서의 위치

M4는 그룹 40개를 크기·맥박·발광을 가진 천체로 그렸다. 새 그룹은 즉시 나타나고 사라진 그룹은 즉시 없어진다. 계약서 8절의 M5 완료 조건은 "파티클 수렴 생성, 붕괴, 클릭 시 자식 전개" 다.

## 2. 측정: 실제로 무엇이 일어나는가

설계 전에 실제 엔진(`--serve`, Debug 빌드, 본 개발 PC)에 붙여 72초 동안 스냅샷 47개를 받아 분석했다.

```
lifecycle.spawned      7건   전부 이미 보이는 그룹의 자식 (whale.exe 5, node.exe 1, bash.exe 1)
lifecycle.terminated  10건   보이는 그룹의 자식 7, 목록 밖 3, 보이는 그룹의 루트 0
이벤트가 있던 스냅샷   46개 중 7개, 한 스냅샷 최대 4건

그룹 key 목록 변화     진입 44회, 이탈 44회
  그중 실제 종료 때문   0회
  드나든 key          12개, 모두 순위 36~40위, 45 MB 이하
  최다                codex.exe:33028 — 46번 중 20번

자식 수                Code.exe 28, whale.exe 22, Figma.exe 13, claude.exe 12 … 40개 중 27개는 0
스냅샷 간격            1,546 ~ 1,589 ms   (hello.interval_ms 는 1000)
```

세 가지 사실이 설계를 정한다.

1. **가장 자주 보일 연출은 자식 프로세스의 생성·종료다.** 루트의 생성·종료는 드물다. 자식은 평소 접혀 있으므로(계약서 D5) 연출은 부모 천체에서 일어나야 한다.
2. **목록은 거의 매초 한 번 바뀌고, 그 원인은 종료가 아니라 경계 순위의 미세한 점수 변동이다.** 엔진 필터가 상태 없이 매 샘플 `cpu% + mem%` 로 순위를 다시 매기기 때문이다. M4에서는 작은 천체가 매초 어딘가에서 깜빡인다.
3. **실제 주기가 1000 ms가 아니라 약 1.55초다.** `EngineLoop` 가 샘플링을 마친 **뒤에** 1000 ms를 쉬므로 주기 = 샘플링 시간 + 1000 ms가 된다. 보간기는 hello의 1000 ms를 믿고 1초 만에 목표값에 도달한 뒤 약 0.5초 멈춘다 — M4에서 이미 매 주기 끊김이 있다.

## 4. 엔진

### 4.1 유지 보너스

`FilterConfig` 에 `incumbent_bonus = 2.0` 을 더한다. `ProcessFilter::select` 는 직전 선택 결과의 key 집합을 받아, 그 안에 있는 그룹의 점수에 보너스를 곱한다. 직전 집합은 `DataAggregator` 가 선택 직후 저장한다. 첫 샘플은 빈 집합이다.

- 보너스는 계정 보너스(user ×1.5)와 곱해진다.
- 그룹 key 는 `이름:루트pid` 이므로 같은 프로그램이 재시작하면 새 그룹이다 — 보너스를 이어받지 않는다. 의도된 동작이다.
- 값은 시제품으로 같은 조건(72초, 실제 엔진)을 세 번 재서 정했다. 부하가 매번 조금 다르므로 초당 비율로 비교한다:

  | 보너스 | 간격 수 | 목록 진입 | 간격당 |
  |---|---|---|---|
  | 없음 (M4) | 46 | 44 | 0.96 |
  | ×1.25 | 72 | 30 | 0.42 |
  | ×2.0 | 72 | 9 | 0.13 |

  ×1.25 로는 부족했다. 경계 순위(약 53 MB, CPU 0%)의 점수는 CPU 0.0↔0.1% 같은 작은 흔들림이 상대적으로 크게 작용한다. ×2.0 에서 새로 들어오려면 경계 그룹 점수의 두 배가 필요하지만, 의미 있는 새 프로그램(수백 MB, 또는 CPU 사용)은 쉽게 넘는다.
- 인수 조건: 같은 측정에서 간격당 목록 진입이 0.2 이하.

### 4.2 고정 주기

`EngineLoop` 는 루프 시작 시각 `t0` 를 기억하고 n번째 샘플 뒤 `t0 + interval × (n+1)` 까지 잔다. 기존처럼 조각(slice) 단위로 자며 `stop()` 에 즉시 반응한다.

- 샘플링이 주기보다 오래 걸려 이미 늦었으면 쉬지 않고 바로 다음 샘플을 뜨고, 기준 시각을 현재로 다시 잡는다. 밀린 주기를 몰아서 따라잡지 않는다.
- 시계는 `std::chrono::steady_clock`.

계약서에는 `hello.interval_ms` 가 "샘플 시작 간격" 이라는 설명을 덧붙인다.

시제품 측정: 스냅샷 간격 최소 985 · 중앙값 1001 · 최대 1013 ms (수정 전 1546~1589 ms).

## 5. 존재 추적 (`visual/presence.ts`)

순수 TypeScript. 키마다 상태 기계 하나.

```
          새 key (spawned 에 루트 pid)           새 key (그 외)
               ↓                                     ↓
           forming (1.2 s) ──────┐          fading-in (0.6 s)
                                 ↓                   ↓
                              present ←──────────────┘
                     key 사라짐 ↓            ↓ key 사라짐
        (terminated 에 루트 pid)              (그 외)
           collapsing (1.0 s)              fading-out (0.6 s)
                 ↓                              ↓        ↑ key 재등장 → fading-in
               제거                            제거        (현재 투명도에서 이어서)
```

입력은 매 프레임 `(현재 그룹 목록, 이번에 소비한 lifecycle 이벤트, 현재 시각)` 이다. 출력은 항목 목록이며 각 항목은 `{ key, phase, progress 0~1, group }` 을 가진다. 떠나는 항목의 `group` 은 **마지막으로 본 값을 고정한 것**이다 — 사라진 그룹의 값은 더 이상 오지 않는다.

- 첫 스냅샷의 그룹들은 전부 `present` 로 시작한다. 앱을 열 때 40개가 한꺼번에 페이드인하지 않는다.
- 세션이 바뀌거나 스토어가 비면 추적기를 비운다.
- 같은 추적기를 Focus 위성(자식, key = pid)에도 쓴다. 입력만 다르다.

렌더링 매핑:

| phase | 크기 배율 | 불투명도 |
|---|---|---|
| forming | easeOutCubic(p) | p |
| fading-in | 1 | p |
| present | 1 | 1 |
| fading-out | 1 | 1 − p |
| collapsing | 1 − easeInCubic(p) | 1 − p² |

노드는 불투명도를 위해 `transparent` 재질을 쓴다. 불투명도 1일 때는 `transparent = false` 로 두어 정렬 비용과 깊이 문제를 피한다.

## 6. 수명 이벤트 소비 (`visual/lifecycleEvents.ts`)

`lifecycle` 은 한 주기 내내 같은 값으로 통과한다(M3 스펙). 매 프레임 그대로 읽으면 같은 이벤트를 60번 연출한다.

- 소비기는 마지막으로 소비한 `seq` 를 기억하고, 현재 스냅샷의 `seq` 가 그와 다를 때만 이벤트를 내보낸다.
- 재전송(같은 seq·t)은 스토어가 이미 거른다. 세션 변경·스토어 비움 시 소비기를 초기화한다.
- 종료된 pid 를 그룹에 대응시키기 위해 **직전 스냅샷**의 루트·자식 pid → 그룹 key 표를 쓴다. 종료된 프로세스는 현재 스냅샷에 없기 때문이다.

출력 이벤트:

| 이벤트 | 조건 | 연출 |
|---|---|---|
| `group-born` | 그룹 key 가 이번에 처음 목록에 나타났고, 그 root_pid 가 생성(spawned)된 지 5 스냅샷 이내 | 존재 추적기가 forming 으로 처리 |
| `child-born` | spawned.pid 가 현재 스냅샷 어떤 그룹의 자식 | 그 그룹으로 작은 수렴 버스트 (24개) |
| `group-died` | terminated pid 가 직전 스냅샷 그룹의 root_pid | 존재 추적기가 collapsing 으로 처리 |
| `child-died` | terminated pid 가 직전 스냅샷의 자식 | 그 그룹에서 작은 내파 버스트 (24개) |

**최근 생성 창 (5 스냅샷).** 루트가 spawned 로 알려진 스냅샷과 그룹이 목록에 처음 나타난 스냅샷이 같지 않을 수 있다. 실제 측정에서 mspaint 와 메모장은 생성과 같은 초에 목록에 들어와 forming 으로 연출됐지만, 새 Edge 창은 생성 3초 뒤에야 목록에 들어왔고(로딩 중 99 MB) 페이드인만 됐다. 그래서 소비기는 spawned 된 pid 를 5 스냅샷 동안 기억하고(목록 밖이어도), 그룹 key 가 직전 스냅샷에 없다가 나타났을 때 그 root_pid 가 그 창 안에 있으면 `group-born` 을 낸다. 같은 스냅샷에서 생성과 진입이 겹치는 경우도 이 규칙 하나로 처리되며, `group-born` 을 낸 뒤에는 그 pid 를 창에서 지우므로, 창 안에서 목록을 나갔다 다시 들어와도 생성 하나당 한 번만 발생한다. 창은 세션 변경·스토어 비움 시 비운다.

목록 밖 프로세스의 이벤트(2절: 10건 중 3건)는 연출하지 않는다.

## 7. 파티클 (`visual/bursts.ts`, `scene/Particles.tsx`)

버스트는 `{ kind: 'converge' | 'implode' | 'scatter', originKey, count, startSec, durationSec, seed }` 다. 입자 i의 위치는 순수 함수로 계산한다:

- **converge**(생성): 반지름 `R × 3.5` 구면의 해시 방향에서 출발해 easeInCubic 으로 중심에 모인다. 도착할수록 밝아졌다가 사라진다.
- **implode**(자식 종료): 표면에서 출발해 중심으로 빨려 들어가며 어두워진다.
- **scatter**(그룹 붕괴): 표면에서 바깥으로 흩어지며 사라진다.

기준점은 **매 프레임의 노드 위치**다 — 떠다니는 노드를 따라간다. 노드가 이미 제거됐으면 마지막 위치를 쓴다.

렌더링은 `Points` 하나, `BufferGeometry` 위치·색·크기 속성 2048개, 가산 블렌딩. 풀이 가득 차면 가장 오래된 버스트를 버린다. 크기 감쇠(`sizeAttenuation`)는 켠다.

| 연출 | 입자 수 | 시간 |
|---|---|---|
| 그룹 형성 (converge) | 160 | 1.2 s |
| 그룹 붕괴 (scatter) | 200 | 1.0 s |
| 자식 생성 (converge) | 24 | 0.8 s |
| 자식 종료 (implode) | 24 | 0.8 s |

## 8. 배치 보완

M4의 레이아웃은 새 key를 key 해시 위치(반지름 18 구 안)에 놓는다. 무리 안쪽에서 생기면 형성 연출이 다른 천체에 가려진다. 사전 수렴이 끝난 뒤 들어오는 key는 **현재 무리의 가장 먼 노드 거리 + 4** 의 구면, key 해시 방향에 놓는다. 사전 수렴 동작은 그대로다.

## 9. Focus 와 카메라

### 9.1 상태

`scene/focusStore.ts` — Zustand 스토어 `{ focusedKey: string | null, focus(key), clear() }`. 장면과 Canvas 밖 DOM 패널이 함께 읽는다. 프레임 값은 들어가지 않는다.

- **들어가기**: 천체 클릭 (`onClick`, 드래그와 구분되는 R3F 기본 동작).
- **나오기**: `Esc`, 빈 곳 클릭(`onPointerMissed`), 초점 천체 재클릭, 초점 그룹이 fading-out·collapsing 에 들어감, 대시보드로 전환(장면 언마운트).
- 다른 천체 클릭: 초점을 그쪽으로 옮긴다.

### 9.2 카메라

GSAP이 `progress` (0→1, 1.0초, `power2.inOut`) 하나만 트윈한다. 매 프레임 카메라는 두 자세를 `progress` 로 섞는다:

```
전경 자세   위치 (0, 10, 58)                        주시점 (0, 0, 0)
초점 자세   위치 = 노드 위치 + 방향 × 거리            주시점 = 노드 위치
            방향 = 전환 시작 시 카메라→노드 반대 방향 (정규화)
            거리 = 노드 반지름 × 7 + 6
```

- 주시점이 매 프레임 노드의 현재 위치이므로 부유하는 천체를 따라간다.
- 초점을 다른 천체로 옮기면 현재 섞인 자세에서 새 초점 자세로 다시 트윈한다.
- 초점 중 `OrbitControls` 는 켜 둔다(그 천체 주위를 돌려 볼 수 있다). 자동 회전은 끈다. 초점을 풀면 M4처럼 사용자가 조작하기 전까지 자동 회전한다.
- 순수 계산(자세 섞기, 초점 자세)은 `visual/camera.ts`. GSAP 과 three 는 scene 쪽에만.

### 9.3 나머지 천체

초점 중 다른 천체의 발광·불투명도에 `1 − 0.75 × progress` 를 곱한다. 호버와 클릭은 그대로 된다.

### 9.4 자식 위성

초점 그룹의 `children` 을 위성으로 그린다. 위성도 존재 추적기(key = pid)를 거친다.

- **궤도**(`visual/orbits.ts`): 궤도 반지름 = `R × 1.8 + 1.2 + 0.35 × 고리`, 고리(0~3)·궤도면 기울기(±54°)·방향·위상은 모두 pid 해시, 각속도 `0.25 rad/s × (R×1.8 / 궤도반지름)`. 결정적이다. 고리를 자식 목록의 순번이 아니라 pid 해시로 정하는 이유: 자식 하나가 생기거나 끝나면 순번이 밀려 다른 위성들이 다른 궤도로 튄다.
- **크기**: `radiusFor(child.mem_mb) × 0.45`. 부모보다 작아 보이게 누른다.
- **맥박·발광**: 자식 자신의 `cpu_pct` 로 M4와 같은 매핑. `null` 은 기본 호흡.
- **펼쳐짐**: 위성의 궤도 반지름에 `progress` 를 곱한다 — 초점이 잡히면서 중심에서 바깥으로 퍼진다.
- 초점 중 자식이 생성되면 위성이 forming 으로, 종료되면 collapsing 으로 들어간다 (`child-born`/`child-died` 버스트는 위성 자리에서 재생).
- 위성 호버 툴팁: 이름, pid, MB, CPU.

### 9.5 초점 패널

Canvas 밖 DOM 패널(우측). 그룹 이름·루트 pid·계정·실행 경로·합계(MB, CPU, 프로세스 수, 스레드 수)와 자식 표(이름·pid·MB·CPU). 값은 M3의 `useInterpolated`(10 Hz)로 읽는다 — Canvas 밖이므로 장면을 다시 그리지 않는다. 숫자 형식은 대시보드의 `formatMb`·`formatPct`.

## 11. 실패 동작

| 상황 | 동작 |
|---|---|
| 한 스냅샷에 이벤트가 많음 | 풀이 차면 오래된 버스트부터 버린다. 화면이 입자로 뒤덮이지 않는다 |
| 초점 그룹이 사라짐 | 초점을 풀고 전경으로 돌아간다 |
| 초점 중 대시보드로 전환 | 장면이 언마운트되며 초점 상태를 비운다 |
| 탭 복귀로 큰 dt | 진행도는 시각 기반이라 한 번에 끝 상태로 간다. 밀린 연출을 몰아서 재생하지 않는다 |
| 세션 변경 | 추적기·소비기·버스트·초점 모두 비운다 |
| 엔진 샘플링이 주기보다 느림 | 쉬지 않고 다음 샘플, 기준 시각 재설정 (4.2) |

## 12. 테스트 전략

| 대상 | 검증 |
|---|---|
| `ProcessFilter` | 보너스 없이는 탈락할 기존 그룹이 보너스로 남는다. 새 그룹이 1.25배를 넘게 앞서면 들어온다. 개수 불변. 빈 직전 집합 = 기존 동작 |
| `DataAggregator` | 연속 두 번 집계에서 직전 선택이 다음 필터에 전달된다 |
| `EngineLoop` | 느린 가짜 리더(샘플 30 ms, 주기 50 ms, 5회)의 총 경과가 `4 × 50` 에 가깝고 `4 × 80` 보다 확실히 작다 (넉넉한 오차). 늦은 샘플 뒤 몰아서 따라잡지 않는다. `stop()` 즉시 반응 |
| `presence` | 표의 모든 전이, 첫 스냅샷은 present, 재등장 시 불투명도 연속, 떠나는 항목의 값 고정, 초기화 |
| `lifecycleEvents` | seq 당 한 번, 같은 seq 재호출은 빈 결과, 네 이벤트 분류, 직전 스냅샷으로 종료 pid 대응, 목록 밖 무시, 초기화 |
| `bursts` | 시작점·끝점, 기간 밖 비활성, 결정성, 풀 한도와 오래된 것부터 버림 |
| `orbits`, `camera` | 결정성, 반지름·거리 공식, progress 0/1 에서 양 끝 자세 |
| `layout` | 사전 수렴 이후 새 key 가 무리 바깥에 놓인다 |
| `Shell` | `event.key` d 로도 전환, 장면 오류 뒤 D 키 동작 (M4 이월) |
| `focusStore`, `FocusPanel` | jsdom: 초점 설정·해제, 패널이 자식 표를 보여준다 |

브라우저 확인:

- 프로그램을 켜고 끄면 해당 천체가 파티클로 형성·붕괴한다. 브라우저 탭을 열고 닫으면 whale 천체에 작은 수렴·내파가 보인다.
- 72초 들락거림 재측정 (before 44회)
- 천체 클릭 → 카메라가 다가가고 위성이 펼쳐지며 패널이 뜬다. Esc·빈 곳 클릭으로 돌아온다. 초점 중에도 천체가 떠다니는 것을 카메라가 따라간다.
- 보간이 매 주기 멈추지 않는다 (스냅샷 간격이 약 1000 ms).
