# 태양계형 배치 설계

- 작성일: 2026-09-30
- 상태: 승인 대기
- 선행: M4 스펙(배치 6절), M5(형성·붕괴), M6(코어 고리), M7(흐름), M1~M9·ETW 구현 (`main`)
- 범위: 프로세스 그룹 천체의 배치를 힘 시뮬레이션에서 "메모리 순위로 나눈 동심원 궤도" 로 바꾸고, 가운데에 시스템 별을, 궤도에 궤도선을 그린다. 엔진과 계약은 바꾸지 않는다.

## 1. 문제

M4 의 배치는 반발·충돌·중심 인력으로 이루어진 힘 시뮬레이션이다. 중심 인력이 반지름의 제곱에 비례해 큰 천체가 가운데로 모이도록 했는데, 실제 화면(사용자 스크린샷, 2026-09-30)에서는 큰 천체 7~8 개가 서로 겹쳐 가운데에 하나의 덩어리로 보인다. 어느 것이 무엇인지, 무엇이 큰지 읽을 수 없다.

## 2. 측정 (실제 스냅샷, 그룹 40 개)

| | 값 |
|---|---|
| 메모리 | 3,877 MB (whale) ~ 47 MB (codex). 상위 7 개가 805 MB 이상 |
| 반지름 (`0.25·∛mem`) | 0.90 ~ 3.93, 중앙값 1.13 |
| CPU 를 쓰는 그룹 | 5 개. 35 개는 0% |

CPU 순위로 궤도를 나누면 35 개가 한 궤도에 몰린다. 메모리는 고르게 퍼져 있어 궤도를 나누기 좋다 (사용자 선택: 메모리 순위).

탐색 스케치 (평면, 탐욕 채우기, 한 궤도를 둘레의 75% 까지): 궤도 3 개 — 반지름 8.5 (4 개), 17.3 (18 개), 23.2 (18 개). 가장 바깥 천체의 끝이 약 27 이다.

## 3. 확정된 결정

| # | 결정 | 이유 |
|---|---|---|
| D59 | 그룹을 반지름(= 메모리) 내림차순으로 안쪽 궤도부터 채운다. 같으면 key 순 | 사용자 선택. 순위가 잘 바뀌지 않아 천체가 궤도를 자주 옮기지 않는다 |
| D60 | 모든 궤도는 XZ 평면이다. 천체는 궤도를 따라 공전하고, 안쪽일수록 빠르다 (케플러처럼 `ω ∝ r^-1.5`) | 태양계를 닮은 체계. 한 평면이라 위에서 내려다보면 한눈에 읽힌다 |
| D61 | 궤도·자리가 바뀌면 천체는 극좌표(반지름, 각)에서 부드럽게 옮겨 간다 | 순간이동하지 않는다. 극좌표로 옮겨야 가운데를 가로지르지 않는다 |
| D62 | 가운데에 시스템 별. 크기 고정, 밝기는 `system.cpu_pct` | 궤도의 중심이 비어 보이지 않게 하고, 전체 부하를 한눈에 보인다 |
| D63 | 코어 고리의 최소 반지름을 28 → 34 로 키운다 | 가장 바깥 궤도(끝 약 27) 밖에 둔다 |
| D64 | 카메라 개요 자세를 위에서 비스듬히 내려다보게 바꾼다 | 평면 배치라 지금의 거의 수평인 시선으로는 궤도가 겹쳐 보인다 |

### 3.1 되돌리기 쉬운 것과 어려운 것

궤도 간격·채움 비율·공전 속도·전환 시간은 `visual/orbits.ts` 상수다. 되돌리기 어려운 것은 없다 — 배치는 `layout.position(key)` 뒤에 숨어 있어 장면의 다른 부분(노드, 툴팁, 카메라 추적, 위성, 흐름, 입자)은 바뀌지 않는다.

## 4. 궤도 계획 (`visual/orbits.ts`, 순수)

`planOrbits(nodes: readonly LayoutNode[]) -> OrbitPlan`

```
OrbitPlan {
  rings: { radius: number; keys: string[] }[]   // 안쪽부터
  outerRadius: number                           // 가장 바깥 궤도 + 그 궤도의 가장 큰 천체 반지름
}
```

- 반지름 내림차순, 같으면 key 오름차순으로 정렬한다.
- 첫 궤도 반지름 = `STAR_RADIUS + STAR_GAP + (첫 천체 반지름)`.
- 궤도 하나에 천체를 차례로 넣는다. 천체 하나가 차지하는 호 길이는 `2r + ARC_GAP`. 합이 궤도 둘레의 `FILL` 비율을 넘으면 다음 궤도로 넘어간다 (궤도에는 최소 1 개).
- 다음 궤도 반지름 = 이전 궤도 반지름 + 이전 궤도의 가장 큰 천체 반지름 + 다음 궤도의 첫(= 가장 큰) 천체 반지름 + `RING_GAP`. 이웃 궤도의 천체는 서로 닿지 않는다.
- 결정적이다: 같은 입력이면 같은 계획.

## 5. 궤도 배치기 (`visual/layout.ts` 의 `LayoutSim` 교체)

`OrbitLayout` 이 `LayoutSim` 과 같은 모양의 API 를 가진다: `step(nodes, dtSec)`, `position(key)`, `size`. `floatOffset`·`floatingPosition` 은 그대로다.

- 궤도마다 회전각 `spin[ring]` 을 **누적**한다: `spin += ω(radius) · dt`, `ω = SPIN_AT_REF · (REF_RADIUS / radius)^1.5`.
- 궤도 k 의 i 번째 천체의 목표 각 = `spin[k] + 2π·i / (궤도의 천체 수) + (궤도마다 key 해시로 정한 고정 오프셋)`.
- 천체마다 현재 극좌표(반지름, 각)를 들고, 목표로 지수 평활한다 (시간 상수 `SETTLE_TAU`). 각은 가장 짧은 호로 따라간다. 목표 각이 매 프레임 조금씩 도는 공전 자체는 평활 뒤에도 그대로 따라간다.
- 비어 있던 배치기에 처음 들어온 천체는 곧바로 목표 자리에 놓는다 (첫 화면이 이미 정리된 모양).
- 그 뒤에 들어온 천체는 `outerRadius + OUTSIDE_MARGIN` 에서 자기 목표 각으로 나타나 궤도로 들어온다 (M5 형성 연출이 다른 천체에 가려지지 않게 — 지금과 같은 규칙).
- 사라진 key 는 잊는다 (붕괴 연출은 M5 의 presence 가 마지막 위치로 한다 — 지금과 같다).
- `dtSec` 이 NaN·음수면 0, `MAX_DT` 로 자른다 (지금과 같은 규칙).
- `y` 는 0 이다. 부유(`floatOffset`)는 그리는 쪽에서 더한다.

## 6. 그리기

- `scene/SystemStar.tsx`: 원점의 구. 반지름 `STAR_RADIUS`. 색은 따뜻한 흰색, 밝기(선형 HDR 배율)는 `system.cpu_pct` 에 따라 `STAR_GAIN_MIN ~ STAR_GAIN_MAX`. Bloom 을 받는다. 초점 중에는 다른 천체처럼 어두워진다. 포인터 이벤트 없음.
- `scene/OrbitRings.tsx`: 계획의 궤도마다 가는 원. 낮은 불투명도, 가산 혼합, 깊이 쓰기 없음. 초점 중에는 더 흐려진다.
- 둘 다 `OrbitLayout` 의 현재 계획을 읽는다 (`layout.plan()`).
- `visual/camera.ts` 의 `OVERVIEW_POSE` 를 궤도가 보이는 각도로 바꾼다. 값은 시제품에서 정한다.
- `visual/coreRing.ts` 의 `RING_MIN_RADIUS` 를 34 로.

## 7. 실패 동작

- 그룹이 0 개: 궤도 없음, 별만 보인다.
- 그룹이 아주 많거나 모두 커서 가장 바깥 궤도가 코어 고리를 넘을 수 있다 (`--max-groups` 를 크게 준 경우). 이번에는 막지 않는다 — 기본 40 개에서는 끝이 약 27 로 34 안이다. 넘으면 천체와 코어가 겹쳐 보일 뿐 기능은 같다.

## 8. 테스트

| 대상 | 방식 |
|---|---|
| `planOrbits` | 정렬(반지름 내림차순, 같으면 key), 궤도 용량(FILL), 이웃 궤도 천체가 닿지 않음, 첫 궤도가 별 밖, 결정성, 빈 입력 |
| `OrbitLayout` | 첫 step 에 목표 자리, 새 key 는 바깥에서 시작해 수렴, 사라진 key 잊음, 궤도가 바뀌어도 한 프레임 이동이 작다(순간이동 없음), 안쪽 궤도가 더 빨리 돈다, NaN·음수 dt, 결정성 |
| `layout.test.ts` 의 기존 `LayoutSim` 테스트 | 힘 시뮬레이션 전용 성질(충돌, 무게중심)은 지우고, API 성질(추가·삭제, dt 처리, `floatingPosition`)은 `OrbitLayout` 으로 옮긴다 |
| 장면 | 컨트롤러가 실제 엔진에 붙여 스크린샷으로 확인 |

## 9. 완료 조건

- 테스트·타입체크·린트·빌드 통과.
- 실제 엔진 화면에서: 가운데 별, 동심원 궤도 몇 개, 큰 천체가 안쪽 궤도에 겹치지 않고 놓임, 바깥에 코어 고리. 이전 스크린샷과 비교.
- 천체가 천천히 공전하고, 새 프로세스가 바깥에서 들어와 자리를 잡는다. 순위가 바뀐 천체는 튀지 않고 옮겨 간다.
- Focus·툴팁·흐름·위성이 전처럼 동작한다.
- 프레임 시간이 M9 수준을 유지한다 (배치 계산이 O(n²) → O(n log n) 이라 나빠지지 않아야 한다).

## 10. 범위 밖

궤도 기울기, 별 툴팁, 궤도 라벨, `--max-groups` 가 클 때의 코어 고리 자동 확장.
